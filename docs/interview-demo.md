# 本地面试演示：知研专题研究工作流助手

目标岗位：AI应用／Agent开发。建议5—8分钟，主线只讲一次研究任务，不逐个展示全部按钮。

## 演示前

1. 启动Docker Desktop及已有Milvus：`docker compose up -d`；已有索引不要运行`ingest`。
2. 使用项目虚拟环境启动`python -m research_agent.cli web`，打开服务提供的本地网址。不要直接打开静态HTML。
3. 核对运行配置及最新收口报告。生成模型通过DeepSeek API调用；本地部署的是网页、资料检索与存储，不声称完整离线推理。
4. 预先打开一份真实运行记录、原始证据和人工可核查的复核说明。现场若外部服务不可用，明确使用已保存真实结果或标为模拟的演示，不把模拟输出当实测。

## 现场顺序

| 时间 | 操作 | 解释的工程问题 |
|---|---|---|
| 0—1分钟 | 输入“核对安亭志的编纂、人物志卷数及现代整理版本，逐项引用证据” | 研究与普通聊天分开；任务需要可检查的计划与中间成果 |
| 1—2分钟 | 展示3个子问题，编辑并确认 | 用户可以修改范围，确认后锁定计划；这是受控工作流而非无限自主循环 |
| 2—4分钟 | 查看逐题取证、证据快照及缺口 | BGE-M3/Milvus负责本地检索，模型负责基于证据组织回答；召回不等于充分支持 |
| 4—5分钟 | 展示联网许可及拒绝后的行为 | 未经许可不搜索；没有出现许可请求时不宣称当前任务验证了该分支，改用标明模拟的已有授权测试演示 |
| 5—6分钟 | 刷新页面，展示阶段成果；打开下载报告 | 后台执行不依赖浏览器连接；报告和证据保存在任务记录中 |
| 6—8分钟 | 展示计划暂停后跨进程恢复记录，再展示一例未通过优化 | SQLite checkpoint恢复执行位置；成本下降仍可能伴随P95或质量退化，所以保留回退 |

固定编辑计划的3个问题：清代编纂者与现代标点者、人物志初稿与编入后的卷数、现代整理本出版信息及版本差异。不要把标准答案加入模型输入。

## 三张解释卡

**架构与边界**：普通问答为受控工具循环；研究为单Agent的LangGraph StateGraph。SQLite保存会话及checkpoint，任务JSON作为视图。当前是单进程、单个活动研究任务，不宣称多进程协调。

**恢复与调用边界**：计划确认和联网许可通过interrupt暂停；已经保存的节点成果在继续时复用。外部调用成功但尚未保存就退出时，恢复可能再次调用，不能保证付费请求恰好一次。

**质量与取舍**：分开看证据命中、答案完整、引用语义支持和拒答。提示词与合法引用标签不能保证事实正确。单变量实验保留失败；未通过当前业务验收的候选不开默认。

## 真实验收与备用入口

本轮已保存的真实结果：[运行记录与11项流程检查](../eval/results/interview_demo_20261101.json)、[原始研究报告](../eval/results/interview_demo_20261101.md)、[内容复核与局限](../eval/reports/interview_demo_review_20261101.md)、[统一验收状态表](../eval/reports/interview_completion_20261101.md)。先打开这些结果即可展示，不必再次调用模型。

如需在网页查看保存的任务，在项目根目录的新PowerShell窗口执行：

```powershell
$env:CONVERSATION_DIR = Join-Path (Get-Location) 'eval/runtime/interview_demo_20261101/conversations'
.\.venv\Scripts\python.exe -m research_agent.cli web --port 8766
```

打开`http://127.0.0.1:8766`，从研究任务列表选择已完成的安亭志任务，查看计划、来源及下载。任务ID为`e937d531bcaa43aca4b3fb3209836cc1`。该目录是本机隔离演示产物，包含checkpoint，未提交Git；若目录缺失，仍可直接展示上面的已保存JSON与Markdown，不能将它当作已完成备份恢复。端口被占用时换一个空闲端口，勿关闭已有活动服务或同时让两个进程操作同一任务目录。关闭此窗口结束临时环境配置，不修改`.env`。仅浏览和下载不调用模型，创建新任务或再次执行会计费。

`eval/interview_demo.py --output 新结果路径`会产生真实API用量，共用原10元账本。它先在一个Python进程生成并编辑计划，再在另一个进程恢复确认执行；使用`eval/runtime/`新任务目录，不重启个人服务或操作已有任务。结果中的不同PID和计划一致性证明跨进程恢复，不能把它描述成已经现场重启了用户的服务器。

无API的恢复和授权备用演示见`scripts/manual_workflow_demo.py`与研究工作流说明。备用演示必须标明模拟。
