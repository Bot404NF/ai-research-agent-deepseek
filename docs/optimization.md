# 面试导向的本地优化

## 当前目标

面向AI应用／Agent开发岗位，优先做到本地演示稳定、工作流可解释、结果有证据、技术取舍诚实。网页、资料和向量计算在本地，生成调用DeepSeek API；不将其描述为完整离线系统。

## 本轮精简范围

| 项目 | 处理 |
|---|---|
| Flash、Embedding进程复用、安全隔离、SQLite持久化和授权边界 | 保持现有实现 |
| 暂停中的混合检索入口 | 已撤下未实现的入口与配置，不继续建设 |
| 运行观测 | 收敛为本地阶段耗时、逻辑调用数、状态和实际usage；不记录正文和凭据 |
| 直接引文检查 | 仅离线诊断，不默认改写或追加未验证的用户提示 |
| 检索质量 | 只实验明确著录问题优先保留CIP／ISBN／版次片段；不重建索引，不做参数扫描 |
| 统一验收 | 仍用同一100题，保留原始答案、AI审核、失败与退化；不按新老题标记 |
| 研究演示 | 一条安亭志真实研究链路，验证计划编辑、跨进程继续、授权边界、报告和HTTP下载 |
| 面试材料 | 简历可用表述、架构与技术问答、5—8分钟演示脚本 |

当前默认采用状态见[本轮收口报告](../eval/reports/interview_completion_20261101.md)：轻量诊断默认开启，检索候选和本地追问保持关闭。当前同轮候选为79/82完整正确、76/82引用支持，未达到引用硬门槛；不沿用历史实验成绩开启开关。

## 不在本轮实施

不建设混合检索和独立重排全套实验、答案缓存、上下文裁剪、并发平台、监控服务、应用容器、公网认证、外网部署、完整索引备份恢复或新的健康接口。基础资料备份作为日常维护建议，不扩展成本轮开发项目。

## 验收和边界

代码完成后运行相关测试、完整离线回归及项目配置的lint/format。涉及真实生成时先估算完整运行费用，共用原10元账本并保留未知用量预留；余额不足则不追加预算，不缩小评分分母。

检索候选默认启用要求：同轮正题完整正确不低于对照且至少74/82；引用支持不低于对照且至少80/82；负题拒答18/18；组合题完整正确不低于对照且至少16/17；失败、截断、未审核保留分母。没有通过时保留原默认，不反复生成挑选最好结果。

面试中展示流程成功、效果指标和内容局限三个不同层面。无专家复核和原件校勘时明确属于AI辅助，不宣称全库准确率、生产SLA或付费调用恰好一次。参见[演示脚本](interview-demo.md)、[面试准备](interview-prep.md)、[第四周报告](../eval/reports/week4_completion_20261031.md)。
