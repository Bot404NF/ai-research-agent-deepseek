# 项目说明与技术取舍

[四部分导航](project/README.md) · [验证与证据](project/evidence.md) · [问题与改进方向](project/limitations.md)

## 项目简介

本项目是一个面向中文资料的本地研究助手。用户输入研究目标后，可以编辑并确认计划，系统再逐题从资料库取证，保存阶段结果，检查缺口与版本差异，最后生成带来源的Markdown报告。研究流程使用LangGraph和SQLite checkpoint，计划确认和联网许可是明确的暂停点，服务重新启动后可以继续未完成步骤。RAG侧使用本地BGE-M3和Milvus，生成调用DeepSeek API。项目包含统一100题的检索、答案、引用和拒答评测，保留失败结果，不把标签合法或流程完成当作事实正确。

## 功能概览

- 基于Python、LangChain和LangGraph实现中文资料研究助手，支持可编辑计划、分题取证、任务级联网授权、证据检查及引用报告导出。
- 使用后台单任务执行器和SQLite checkpoint保存执行位置与中间成果，实现计划／授权暂停、失败步骤继续及跨进程恢复；普通问答支持流式输出和完整会话持久化。
- 接入本地BGE-M3与Milvus，管理已核验的28,216个文本块；建立统一100题评测及原始结果、AI复核、费用用量和失败分析记录。
- 为授权边界、任务恢复、流式接口、异常脱敏和测试凭据隔离建立自动化回归；增加不记录正文和凭据的本地阶段诊断。

上述功能已实现。准确率、速度和费用改善只有在说明模型、题集、调用路径和采用状态时才补充，不写成全库质量或生产SLA。此前验收见[收口报告](../eval/reports/interview_completion_20261101.md)：194项测试通过；真实研究9次模型调用、跨进程恢复和HTTP下载验证通过。检索候选79/82完整但76/82引用支持，未采用；这些数字属于固定开发题集的AI辅助审核。

## 技术取舍与常见问题

| 问题 | 说明 | 相关实现与记录 |
|---|---|---|
| 为什么用LangGraph？ | 研究具有明确阶段、人工确认和恢复要求；图状态比一条长提示词更容易保存、检查和继续 | `research_graph.py`、任务JSON、checkpoint、恢复测试 |
| 是多Agent吗？ | 不是，是单Agent工作流。当前没有多个独立协作角色的必要，先保证证据和状态可靠 | 图节点、模型调用链 |
| 为什么用SQLite？ | 本地单用户、单进程执行，SQLite减少运维成本；没有承诺多进程协调或高并发 | 会话存储、任务锁、checkpoint |
| RAG和Agent有什么区别？ | RAG提供证据；Agent负责计划、工具边界、缺证判断、授权和流程推进。检索命中与回答正确需分别评测 | 普通问答和研究两条调用链 |
| 能保证恢复后不重复计费吗？ | 保存的成果可以复用；外部请求成功但尚未落盘便退出时仍可能重复，不能保证恰好一次 | checkpoint边界与失败恢复测试 |
| 本地部署是否意味着资料不离开本机？ | 不是。网页、存储和向量计算在本机；用于回答的选中证据会随请求发给模型API | 配置与实际模型调用 |
| 怎么防止乱用网络或写入索引？ | 确定性先检索、显式联网许可、工具白名单和调用上限；导入与只读研究分开 | 许可测试、工具中间件、入库入口 |
| 如何证明优化有效？ | 冻结题集和参数，比较完整性、引用、拒答、用量与延迟，保留退化和未采用决定 | 统一评测、第四周失败实验、最新验收 |

## 典型案例

1. **成功功能：跨进程继续研究。** 先生成并编辑计划，在确认点退出进程，再由新进程恢复。能解释保存了什么、由谁触发继续，以及没有承诺什么。
2. **质量失败：局部与整体混淆。** 既有M05实验曾找到人物志三卷的证据，却将全志二十卷当作答案。说明检索充分、生成正确和引用支持是不同指标，不能只看Hit@4。
3. **优化取舍：降本不代表可以采用。** 第四周本地追问候选虽然减少调用，但同轮P95及质量未满足门槛，因此没有默认启用。主答案生成有随机性，不能直接把两个错题归因于追问方式。
