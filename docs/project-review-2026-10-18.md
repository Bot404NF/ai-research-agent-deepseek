# 项目检查记录

检查日期：2026-10-18。检查依据为当前工作目录中的源代码、依赖配置、网页脚本和测试文件。

## 范围与架构

已阅读 CLI 与配置、代理工具循环、单轮回答、检索、全量导入、增量更新、资料库管理、会话持久化、联网搜索、HTTP 服务与网页、Docker Compose 和测试配置。未逐份核验资料正文，也未删除、迁移或重建现有资料索引。

主要流程：网页或 CLI → 本地 BGE-M3 → Milvus 检索 → DeepSeek 流式回答 → 来源与追问 → 本地 JSON 会话记录。文件上传先暂存，显式导入时解析、切分、向量化并追加写入。

`pyproject.toml`、`uv.lock` 和 `src/` 均未发现 LangGraph 依赖或调用。项目使用 LangChain 的消息、工具和模型适配，以及普通 Python 循环；会话记忆来自自定义 `ConversationStore`，并非 LangGraph checkpoint。

## 已完成的整理与优化

- 嵌入模型按模型名和解析后的设备缓存，同一进程复用一个模型配置；初始化加锁，避免多个首次请求重复加载权重。CUDA 自动选择、向量归一化和批大小保持原设定。
- 资料库详情在一次请求中复用清单、目录索引和共享集合统计；同一集合统计成功后不再按目录重复查询。保持原返回字段和统计口径。
- 新增通用 JSON 原子写入工具，会话、目录和索引清单统一使用同目录的独立临时文件，替换失败时保留旧文件并清理临时文件。
- 本进程中新建、删除和导入资料库共用修改锁，防止并发清单读改写覆盖其他请求。
- 检索目录改为按标识过滤原始目录，修复原始目录已删除时跳过第一个新增目录的问题；合并跨集合结果后统一分配新增证据标签。
- 来源展示集中处理可选相关性分数，避免分数缺失时格式化异常。
- 网页状态请求增加超时与并发检查，资料库列表请求增加超时和 HTTP 错误处理，避免请求长期无返回时保持“读取中”。
- 离线代理测试隔离真实检索；真实模型集成检查标记为 `integration`，默认不执行。日志、检查临时目录及运行期清单补充到忽略规则。

## 保留的边界与后续事项

- 修改锁只适用于单服务进程。多个进程同时操作同一数据目录，以及同一会话的并发回答，仍需要更完整的事务或任务协调。
- 多个目录共用集合时，当前详情中的文本块数仍沿用集合总数；未改为目录精确计数，以保持原有字段语义。
- Milvus 相似度分数与 `0.55` 门槛尚需用标注问题集校准；当前警告中出现的 L2 默认距离不能当作质量已经验收。
- 网页 Markdown 是本地安全语法子集，不执行原始 HTML，尚未按完整 CommonMark 规范验收。此次只完成脚本语法检查，没有浏览器视觉和点击自动化验收。
- 模型复用减少加载开销，但不代表 GPU 推理吞吐已压测；高并发场景仍需显存与队列管理。
- Python 配置的 Milvus 回退地址为 `19530`，示例环境和 Compose 映射为 `19531`；当前依赖 `.env` 配置正确地址。本次没有改变原默认值。
- HTTP 服务仍是仅绑定 `127.0.0.1` 的本机演示服务；现有检索、联网许可、上传、增量导入、更新、删除、历史会话、Markdown 和追问按钮入口保留。
